# dscan — Kissflow XG Dockerfile Roast Board

A Claude-inspired tracking board over [`droast`](https://github.com/immanuwell/dockerfile-roast)
findings for every microservice Dockerfile in the `kissflow-xg` repo.

Live (local): **https://dscan.localhost** (via [portless](https://github.com/anthropics/portless))

## What's inside

```
kf-board/
├── index.html      # board layout
├── styles.css      # Claude design language (cream/coral palette, Source Serif 4 + Inter)
├── app.js          # filters, status tracking, three views
├── rules.js        # droast rule catalog (DF001..DF064)
├── data.js         # scan results (regenerated by scripts/scan.sh)
└── scripts/
    ├── scan.sh     # rescan kissflow-xg and rewrite data.js
    └── serve.sh    # start/stop the local board on dscan.localhost
```

The board is a single static page — no build step, no framework, no runtime
dependency. State (status pills + per-finding notes) is stored in the
browser's `localStorage`, so each engineer gets their own remediation log.

## Views

- **By service** — collapsible row per microservice, severity pills, fix progress bar
- **All findings** — flat list sorted by severity for triage
- **By rule** — group by droast rule (DF001…) with per-file remediation tracking

Each finding can be marked **Open / In progress / Fixed / Won't fix** and
annotated with a free-text note (e.g. ticket id).

## Quick start

```bash
# 1. (one-time) build droast from source
git clone https://github.com/immanuwell/dockerfile-roast ~/GitHub/tools/dockerfile-roast
cd ~/GitHub/tools/dockerfile-roast
cargo build --release

# 2. (one-time) check out the kf branch with the board
git checkout kf

# 3. scan + serve
cd kf-board
./scripts/scan.sh                 # rebuilds data.js
./scripts/serve.sh start          # serves https://dscan.localhost
```

To stop:

```bash
./scripts/serve.sh stop
```

## Without portless

If you don't have `portless`, the static server is still reachable at
`http://127.0.0.1:7311/` after `serve.sh start`. Or just open `index.html`
directly in a browser — it's a fully static page.

## Regenerating after Dockerfile changes

```bash
./scripts/scan.sh                 # rescans the entire repo
# refresh the browser tab — data.js is reloaded
```

To point at a different repo:

```bash
./scripts/scan.sh /path/to/some/other/kissflow-xg
```

## Why this exists

Auditing 60+ Dockerfiles by hand is tedious and the findings rot fast. The
board gives the team a single screen to triage what's worth fixing, what's
already fixed, and what's been deliberately accepted — all without standing
up a real backend.

Generated with [dockerfile-roast](https://github.com/immanuwell/dockerfile-roast)
on the `kf` branch of the [karunakaranks/docker-scan](https://github.com/karunakaranks/docker-scan/tree/kf) fork.
